# 중단된 생성 작업의 명시적 재개

기준: 2026-11-03. [PR #281](https://github.com/hhj3839/recording/pull/281)이 main에 병합되고 시드니 운영 배포와 제한된 운영 검증을 완료했다.

## 원인과 재현

후속 runner 호출이 네트워크 오류로 실패하면 현재 배치의 저장과 current_batch 증가까지 끝난 작업이 queued에 남는다. 상태 GET은 실행을 시작하지 않으므로 기존 화면에서는 생성 버튼이 계속 비활성화되고 재개할 방법이 없었다.

실제 행동특성 runner를 격리 저장소·모의 생성기로 실행해 두 배치 중 첫 배치 저장 후 후속 fetch를 실패시켰다. 작업은 같은 ID/current_batch=1로 멈췄고 명시적 재개 후 두 번째 배치만 처리했다. 변경 전 실제 Home 화면으로 새 브라우저 검사를 실행했을 때 재개 버튼 부재로 실패했고, 수정 후 통과했다. 운영에 생성 작업을 만들어 재현하지 않았다.

## 수정

- 교과평어·행동특성·평어 풀 화면에 기존 작업 재개 버튼 제공. 화면 진입/상태 조회/시간 경과는 실행 POST를 만들지 않는다.
- GET은 canResume만 계산하며 실행하지 않는다. queued 갱신 후 30초, running 갱신 후 6분 이상 지난 작업만 허용한다. runner maxDuration=300초보다 긴 실행 보호 시간이며, 잘못된 시각과 종료 상태는 거부한다.
- POST /api/generation-jobs/resume는 jobId만 받고 인증 사용자·현재 소유 학급·작업 종류·상태를 다시 확인한다. 없는/다른 범위 작업은404, 진행 중/종료/경합은409.
- ID/소유자/학급/종류/상태/updated_at 조건부 갱신으로 한 재개 요청만 예약한다. 기존 작업을 queued로 전환하고 실행 시간을 갱신할 뿐 batches·current_batch·저장 결과·완료 수는 바꾸지 않으며 새 작업을 생성하지 않는다.
- 기존 runner의 조건부 실행 잠금도 유지한다. comments/pools runner 조회에 작업 종류 필터를 추가해 잘못된 종류의 서명된 전달도 거부한다.
- 재개 전달 실패 시 아직 같은 예약 상태인 작업에만 일반 오류 메시지를 기록한다. 이미 진행된 작업의 상태를 덮어쓰지 않는다. 재개 응답202는 접수이며 완료가 아니다.
- UI는 진행 중 재클릭을 막고 응답 본문까지20초 제한을 둔다. 네트워크/HTML/시간 초과/409 시 버튼을 복구하고 자동 재시도하지 않는다. 현재 평가계획이 비어도 저장된 평어 풀 작업 재개 안내는 표시한다.

- 모의 생성기만 사용하여 유료 AI 호출과 운영 학생 데이터 변경은 없다.

## 보장 범위와 남은 한계

동시 재개 예약과 정상 실행 잠금 안의 중복 배치 실행을 차단한다. 완료된 배치는 current_batch 이후부터 이어간다. 실행 도중 프로세스가 죽은 경우에는 미완료인 현재 배치를 다시 시도할 수 있다. 외부 AI 응답 직후·저장/진행 위치 기록 전의 장애까지 분산 트랜잭션의 exactly-once를 보장하는 기능은 아니다. 실행시간 초과를 보호시간보다 길게 설정할 때는 재개 정책도 함께 조정해야 한다.
