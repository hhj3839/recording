# 교과평어 조회 시 자동 실행 경로 조사

기준: main `3c139fc` (PR #271), 2026-10-31.

## 구분

PR #270의 영역 번호·수준 값 비교는 유지한다. 키 순서 오판은 대상 수 계산 문제이며 생성 호출의 직접 원인은 아니다. PR #271도 자동 시작이 미해결임을 기록했다.

## 확인한 실행 경로

- 교과평어 최초 진입/새로고침: Comments effect → 저장 결과 GET 및 comment-jobs GET. queued/running 작업을 복원하면 3초마다 상태 GET.
- 저장 결과 로딩: generated-comments GET 후 화면 상태만 갱신. 생성 호출 없음.
- 대상 선택창 열기: 대상 수/모드와 모달 상태만 설정. 최종 생성 버튼에서만 comment-jobs POST.
- 평가계획 AI 평어 탭: comment-pools GET 요약/개별 작업 상태 조회. 기존에는 두 경로 모두 활성 작업의 runner를 호출했다.
- 수정 전 comment-jobs GET도 queued/running 작업을 runner에 전달했다. queued 작업과 6분 이상 된 running 작업은 runner의 실행 대상이 된다. 최근 running 작업은 잠금으로 busy를 반환할 수 있으므로 runner 호출과 실제 생성은 구분한다.
- comment-jobs runner는 저장된 공용 문장을 조합·저장한다. comment-pools runner에는 유료 AI 호출 경로가 있다. 이 조사는 실제 운영 호출·과금·저장 변경 발생을 입증하지 않는다.

## 최소 수정

두 API의 GET에서 runner 호출 3곳을 제거한다. POST 생성/기존 작업 재개, 실패 풀 retryFailed, runner의 다음 배치 실행, 인증된 pump는 유지한다. 따라서 이미 승인된 백그라운드 작업은 페이지와 무관하게 계속될 수 있다. 이 변경은 중지/취소 기능이 아니다. pump 설정이 없는 환경에서 runner 연결이 끊기면 이제 화면 조회만으로 복구되지 않는다.

## 격리 검증

실제 route 코드를 transpile하여 데이터 접근·실행기 fetch를 모두 모의 구현했다. 가상 학급 999, 학생 6명만 사용한다. 운영 로그인·학생 데이터 접근·유료 API 호출 없음.

- 수정 전 13개 중 queued/running 조회 4개 실패: GET이 runner를 호출함. 나머지 9개 통과.
- 수정 후 확장 15개 통과: 작업 없음/완료/오류/대기/실행 상태, 반복 조회, 풀 요약·개별 상태·활성 작업 감사, 수동 6명 생성, 명시적 기존 작업 재개, 실패 풀 이어서 제작.
- 실제 페이지의 저장 로딩·선택창 handler를 추출 실행: 초기/재조회 GET만 발생, 저장 문장 동일, 로딩 중 선택 차단, 조회 완료 후 선택창만 열림.
- 기존 수준 비교·로딩 UI·저장 실패·풀 시작/폴링 검사 13개 통과.
- 빌드 성공. 기본 검사 75개 및 TypeScript 정책 검사 142개, 관련 회귀 검사 28개로 총 245개 통과. 기존 operation-safety의 교과평어 GET 자동 재개 기대는 제거하고 행동특성 기대는 유지함.
- 타입 검사 통과. lint 오류 없음(기존 내부 탐색 경고 2개).

브라우저 전체 E2E 및 운영 재현은 수행하지 않았다. 당시 사용자 현상과 이 경로의 일치 여부, 과금·데이터 변경 여부, 운영 pump 활성 여부는 미확인이다.
