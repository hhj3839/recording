## 0. 현재 제품 정책 및 개발 상태

**최종 갱신:** 2026.08.17

이 절은 초기 v1.0 요구사항보다 우선하는 현재 제품 정책임.

### 확정된 정책 변경

* 교과 평가 관찰 메모는 사용하지 않으며 평가계획과 학생별 평가 수준을 근거로 교과 평어를 생성함.
* 행동특성은 영역별 입력 대신 학생당 하나의 `관찰 사실` 입력창을 사용함.
* AI 사실 검수와 별도 최종 확정은 사용하지 않음. 교과 평어와 행동특성 모두 바이트 수, 종결어미, 금지어, 맞춤법 자체 규칙, 반복 및 학급 내 중복률을 표시하고 교사가 화면에서 바로 수정함.
* 교과 평어 후보·문장 수·최대 바이트·작성 방향 설정은 사용하지 않으며 결과는 1개만 생성함.
* 교과 평어는 입력된 평가 영역마다 정확히 1문장을 작성함. 평가기준의 정보량과 수행 요소 수에 따라 단일 수행은 45~65자, 두 수행은 55~75자, 복합 수행은 60~85자를 생성 목표로 사용함. `함.`, `음.`, `임.`, `뛰어남.`, `돋보임.`, `인상적임.` 등 학교생활기록부에 적합한 자연스러운 명사형 종결을 허용하고 `하였다.`, `입니다.`, `할 수 있다.` 같은 서술형 종결은 사용하지 않음. 자연스러운 35~90자 문장은 결과를 보존하고 길이만으로 생성 실패나 화면 오류를 만들지 않음.
* 평가계획 저장 후 교사가 `AI 평어 제작`을 실행하면 평가영역·평가수준별 최대 20개 후보를 생성하고 서버가 통과 문장을 선별함. 학생 생성 시에는 추가 AI 보완을 하지 않고 승인 문장을 즉시 배정함. 승인 문장이 부족하면 중복을 허용하며 표현 다양화보다 입력된 평가수준·교사의 도움·노력·일부 수행 등 필수 의미와 자연스러움을 우선함.
* 각 평가 영역의 수준·평가기준과 함께 `교사의 도움`, `일부 수행`, `노력·성장 과정` 필수 의미와 근거에 없는 강한 표현 금지 지시를 AI 요청에 구조화하여 전달함. 형식·근거 검수에서 탈락한 문장은 해당 영역에 구체적인 확인 사유를 저장함.
* 상·중·하는 각각 잘함·보통·노력 요함에 대응하되 수준 이름만으로 수행이나 태도를 추측하지 않고, 해당 평가계획의 수준별 기준에 명시된 의미만 문장에 반영함.
* 자연스러운 명사형 문장에도 마침표를 필수로 하며 AI가 마침표만 빠뜨린 경우 추가 호출 없이 저장 전에 보완함. `표현하려는 노력함` 같은 비문, 평가기준에 없는 구체적 표현 방법과 학습 태도는 저장 전에 차단함.
* 근거·수준·필수 수행 요소 누락과 완전 동일 후보는 저장 전에 차단함. 같은 평가기준에서 발생하는 구조 유사도는 결과 누락 사유로 쓰지 않고 우선 저장한 뒤 겹친 영역만 한 번 다양화함. 남은 유사 표현은 오류 유형으로 표시하지 않고 학생 간 유사도 참고 정보에만 반영함.
* 선택된 수준 기준에 여러 수행 요소가 연결되어 있으면 나누기·표현하기·파악하기·간추리기 등 모든 요소를 한 문장에 보존함. 60~80자는 생성 목표와 품질 측정 지표이며, 길이만으로 자연스러운 결과를 버리거나 유료 재생성을 늘리지 않음.
* 행동특성은 학생별 키워드 또는 관찰 메모를 한 가지 이상 입력하면 일괄 생성을 시작할 수 있음. 구체적인 입력이 많을수록 결과 품질이 좋아지지만 개수로 생성을 차단하지 않음.
* 행동특성은 문장 수를 고정하지 않고 입력된 키워드·관찰 메모만 바탕으로 500~600B의 자연스러운 한 문단을 생성함. 변화·성장은 입력된 경우에만 반영하고 입력 근거가 없는 영역은 추측하지 않음.
* 교과 평어는 같은 평가계획 의미·평가영역·평가수준별 승인 문장 풀을 먼저 생성함. AI 요청에는 학생 ID를 보내지 않으며 서버가 근거·수준·형식 검사를 통과한 문장만 번호순 학생에게 순환 배정함. 학생 생성 과정에서는 AI를 다시 호출하지 않음.
* 행동특성의 과장·비교·부정 행동 부재를 평가하는 표현은 저장 전에 차단함. 예: `가능성이 크다고 보임`, `흐름을 해치지 않음`, `문제 행동을 보이지 않음`, `항상`, `완벽하게`, `매우 우수함`.
* 교과 평어와 행동특성 일괄 생성은 서버 백그라운드 작업으로 실행되며 페이지를 닫아도 계속 진행하고 결과를 저장함.
* 생성 상태 조회 시 대기 중인 다음 배치를 안전하게 다시 깨워 Vercel 내부 후속 호출이 지연되더라도 열린 화면에서는 다음 평가영역을 빠르게 이어서 처리함. 페이지를 닫은 경우에는 기존 서버 후속 실행과 예약 실행이 계속 담당함.
* AI 평어 제작은 한 영역·수준당 최대 두 번의 후보 생성 요청으로 제한함. 각 요청은 부족 수량을 고려해 20~40개 후보를 받고 독립 규칙 검수 후 최대 20개만 승인함. 학생 교과 평어 생성은 0회 호출이며 행동특성은 실패 학생만 실제 바이트 진단을 포함해 개별 재조정함.
* 학생별 표현 설계표는 시작 방식·전개 순서·문장 구조, 핵심 동사의 위치, 명사형 종결 방식과 구체적인 어순 패턴까지 분산함. 다양화 지시는 표현 방식에만 적용하며 사실성·평가수준·핵심 수행 요소가 항상 우선함.
* 교과 평어 생성 결과는 평가영역 누락·수준 불일치·근거 밖 사실·금지 표현·명백한 서술형 및 비문 종결만 차단함. 공백·줄바꿈·마침표 누락은 서버에서 자동 정리함. 적응형 권장 길이 이탈과 유사 표현은 화면 오류 유형 및 실패 영역 수에서 제외하고, 유사도는 검수 칸의 참고 정보로만 제공함. 경미한 자체 맞춤법은 교사 확인 권장으로 표시함.
* 같은 평가영역·수준의 중복은 완전히 같은 문장, 평가 핵심어를 제외한 4단어 연속 표현·75% 이상 표현 유사도로 무료 판정하고 겹친 영역만 최대 한 번 다시 생성함. 평가기준 때문에 불가피한 첫 구절 일치만으로 중복 판정하지 않되 완전히 같은 문장은 항상 다시 생성 대상으로 분류함. 한 번 보완 뒤에도 유사하면 추가 AI 호출이나 오류 판정 없이 참고용 유사도 정보만 유지함.
* 교과 평어 과목별 생성 버튼은 `결과가 비어 있는 학생`, `마지막 생성 이후 평가수준을 수정한 학생`, `생성 대상 전체`를 선택하는 중앙 창을 표시함. 생성 당시 평가수준을 별도 저장해 새로고침 후에도 수정 대상을 판별함.
* 교과 평어 화면은 `자동 생성·보완 중`, `저장 완료`, `교사 확인 권장`, `생성 실패`를 서로 다른 상태로 표시함.
* 각 평가 영역의 후보는 1개만 생성하고 첫 요청에서 통과한 영역은 즉시 저장하며, 누락·형식 실패 영역만 보완 생성함.
* 나이스 자동입력 매크로는 웹 브라우저 보안 제약으로 현재 개발 범위에서 보류함. 교과 평어와 행동특성 화면에서 번호순 본문 복사를 제공함.
* 전체 결과 공유, Excel·CSV 내보내기, Google Sheets 생성 기능은 코드는 보존하되 현재 사용자 화면에서는 숨김 처리함.
* 교사 파일럿 측정 화면과 API는 제품에서 제거하고 실제 파일럿은 별도 운영 절차로 수행함.

# 1. 프로젝트 개요

## 1.1 앱 이름

**가제:** 기록샘

**설명:**
교사가 과정중심평가 계획과 학생별 평가 수준, 학생 특성을 입력하면 API를 활용하여 교과 평어와 행동특성 및 발달상황 초안을 생성해 주는 생활기록부 작성 지원 웹앱임.

---

## 1.2 개발 배경

### 교실에서 마주한 문제점

초등학교 교사는 학기말마다 학생별 교과학습발달상황과 행동특성 및 발달상황을 작성해야 함. 학생 수가 많고 평가 항목도 다양하여 평가계획과 학생별 평가 결과를 일일이 확인하면서 서로 다른 문장을 작성하는 데 많은 시간이 소요됨.

교과 평어를 작성하려면 다음 내용을 함께 고려해야 함.

* 과목
* 단원
* 평가목표
* 평가 영역
* 평가 유형
* 평가 관점
* 학생의 상·중·하 평가 수준
* 수준별 평가 기준
* 평가상의 유의점

그러나 실제 작성 과정에서는 다음과 같은 어려움이 발생함.

1. 과정중심평가 계획과 학생별 평가 결과를 연결하기 어려움.
2. 같은 평가 수준의 학생에게 유사한 문장을 반복하게 됨.
3. 평가 항목이 많아질수록 학생별 평어 작성 시간이 크게 증가함.
4. 행동특성 작성 시 학생의 여러 특성을 자연스럽게 연결하기 어려움.
5. 입력하지 않은 사실이 문장에 포함되지 않도록 반복 검토해야 함.
6. 모든 문장의 맞춤법, 종결어미, 바이트 수를 직접 확인해야 함.
7. 여러 교사가 각자 다른 방식으로 AI를 사용하여 결과의 일관성이 떨어짐.
8. 학생 개인정보를 일반 생성형 AI 서비스에 직접 입력할 가능성이 있음.

### 기대 효과

* 교과 평어와 행동특성 초안 작성 시간 50% 이상 단축
* 과정중심평가 계획과 교과 평어의 일치도 향상
* 학생별 문장 중복 감소
* 관찰 사실에 근거한 구체적인 행동특성 작성
* 바이트 수와 종결어미 자동 검수
* 교사가 최종 검토와 수정에 집중할 수 있는 환경 제공
* 여러 학교 교사가 동일한 방식으로 안전하게 사용할 수 있는 서비스 구축

**주요 기능:**

* 평가 항목 수정
* 평가 항목 삭제
* 다른 학급 적용 기능은 소수 사용자 운영에 맞춰 제공하지 않음
* 평가계획 버전 저장

**주의사항:**

학생별 평가 결과가 입력된 평가 항목을 수정할 경우 경고를 표시함.

### 기능 8. 과목별 교과 평어 생성

**설명:**
과목별 AI 평어 생성 버튼으로 평가수준이 입력된 전체 학생의 선택 과목 평어를 서버 백그라운드 작업으로 생성함.

**사용 시나리오:**

1. 교사가 학생별 평가 수준을 저장함.
2. 교과 평어 화면에서 AI 평어 생성을 실행함.
3. 페이지를 이동하거나 닫아도 서버에서 작업을 계속함.
4. 생성 결과를 학생·과목별로 저장함.
5. 교사가 과목 탭을 선택해 번호·이름·평어 표를 검토함.

**안전 장치:**

* 미입력·평가 예정·미응시 항목 구분
* 입력된 각 평가 영역마다 정확히 한 문장 생성
* 영역별 50~60자 권장 및 `함.` 종결 검사
* 48~49자와 61~62자는 차단하지 않고 길이 확인 경고 표시
* 누락·중복된 평가 근거 검사
* 학급 내 유사 표현과 중복률 표시
* 성공한 영역 문장은 즉시 영역 단위로 저장
* 실패 영역만 동일 저비용 모델로 최대 3회 추가 재시도
* 세 번의 시도 후 실패한 영역은 `확인 필요`로 표시하고 다른 성공 문장은 유지
* 다음 요청에서는 같은 평가 근거로 이미 저장된 성공 영역을 다시 생성하지 않음
* 페이지 이동 후 작업 상태와 저장 결과 복원

**우선순위:** 상

### 기능 10. 행동특성 입력

**설명:**
학생 이름 옆의 단일 `관찰 사실` 입력창에 실제로 관찰한 특성과 변화 모습을 자유롭게 입력함.

### 입력 가능한 특성 영역

* 학습 태도
* 교우관계
* 책임감
* 생활 습관
* 의사소통
* 협력
* 자기관리
* 성장 모습
* 특별히 강조할 점

**입력 예시:**

```text
학습 태도: 수업에 성실하게 참여하며 궁금한 내용을 질문함
교우관계: 친구의 이야기를 잘 듣고 갈등이 생기면 대화로 해결하려고 함
책임감: 맡은 역할을 끝까지 수행함
생활 습관: 준비물을 스스로 점검하는 습관이 형성되고 있음
성장 모습: 발표를 어려워했으나 최근에는 모둠 앞에서 자신의 생각을 말함
특별히 강조할 점: 배려심, 꾸준함
```

**입력 방식:**

* 학생당 단일 자유 메모 입력
* 8개 영역의 강점·성장 지원 참고자료 제공
* 참고 표현을 클릭하여 현재 학생 입력창에 추가
* 학생별 직접 수정

**우선순위:** 상

### 기능 11. 행동특성 및 발달상황 생성

**설명:**
교사가 입력한 한 가지 이상의 키워드 또는 관찰 메모를 바탕으로 행동특성 및 발달상황 초안을 생성함.

### 작성 원칙

1. 교사가 입력한 학습 태도, 교우관계, 책임감, 생활 습관, 의사소통, 협력, 자기관리, 성장 모습을 중심으로 작성함.
2. 학생의 장점과 발전 가능성이 구체적으로 드러나도록 작성함.
3. 부정적인 관찰 사실은 단순히 완곡하게 반복하거나 숨기지 않고, 행동 안에서 합리적으로 발견할 수 있는 관심·표현 의지·분명한 주관·신중함 등의 긍정적 측면을 먼저 드러낸 뒤 자기조절·경청·협력·집중·표현의 교육적 성장 방향으로 연결함. 입력에 없는 구체적인 개선 성과나 완료된 변화는 만들지 않음.
4. 활동을 단순 나열하지 않고 행동의 특징, 과정, 변화가 나타나도록 작성함.
5. 모든 문장을 `음` 또는 `임`으로 끝냄.
6. 한글 맞춤법과 띄어쓰기를 준수함.
7. UTF-8 기준 500바이트 이상 600바이트 이하로 작성함.
8. 대회 실적, 수상 실적, 사교육, 공인시험, 특정 기관명, 부모의 직업이나 사회경제적 배경을 포함하지 않음.
9. 입력된 사실을 과장하거나 새로운 사실을 추가하지 않음.
10. 학생이 여러 명이면 학생별로 구분하여 모두 작성함.

**우선순위:** 상

### 기능 12. 행동특성 자동 검수

**설명:**
행동특성 생성 결과가 작성 원칙에 맞는지 자동 검사함.

**검수 항목:**

* UTF-8 기준 500~600바이트
* 모든 문장 종결어미가 `음` 또는 `임`인지
* 동일 표현이 반복되는지
* 입력에 변화와 성장 모습이 있을 때 결과에 반영되었는지
* 금지 내용이 포함되었는지
* 부정적이거나 단정적인 표현이 있는지
* 맞춤법과 띄어쓰기 오류가 있는지

**검수 결과 예시:**

```text
바이트 수: 537바이트
종결어미: 정상
성장 모습: 포함
반복 표현: 없음
금지 내용: 없음
```

**현재 정책:** 별도의 AI 사실 검수는 사용하지 않으며 위 항목 중 의미 추론이 필요한 `입력 근거 외 표현` 검사는 제공하지 않음.

**우선순위:** 상

### 기능 13. 행동특성 일괄 생성

**설명:**
학생별 특성이 입력된 학급 전체 학생의 행동특성을 한 번에 생성함.

* 학생별 바이트 수 표시
* 반복 문장 검사
* 학생별 수정
* 500B 미만·600B 초과 결과의 화면 분량 경고와 직접 수정. 생성·저장·감사도 같은 500~600B 정상 범위를 사용함

**제한 조건:**

* 생성 전 개인정보 및 금지 내용 검사

**우선순위:** 상

### 기능 14. 문장 중복 검사

**설명:**
같은 학급의 교과 평어와 행동특성 문장이 지나치게 유사한지 검사함.

**검사 방식:**

**우선순위:** 중

**지원 방식:**

# 5. 교육적 고려사항

## 5.1 교육과정 연계

### 대상

* 초등학교 1~6학년
* 일반 교과목
* 행동특성 및 발달상황

### 연계 정보

* 과목
* 단원
* 평가목표
* 평가 영역
* 평가 유형
* 평가 관점
* 수준별 평가 기준
* 평가상의 유의점
* 학생별 평가 결과

### 교육적 원칙

* AI가 평가 수준을 결정하지 않음.
* 교사가 입력한 평가 결과만 문장으로 변환함.
* 평가계획을 벗어난 내용을 생성하지 않음.
* 학생 간 비교나 서열화를 하지 않음.
* 낮은 평가 수준을 낙인찍는 표현으로 작성하지 않음.
* 학생의 실제 수행과 성장 모습을 중심으로 작성함.

---

## 5.2 학습 및 평가 지원 목표

1. 과정중심평가 계획과 생활기록부 평어를 일관되게 연결함.
2. 학생별 평가 결과를 구체적이고 자연스러운 문장으로 표현함.
3. 교사의 반복적인 문장 작성 부담을 줄임.
4. 학생의 강점과 성장 가능성이 드러나는 기록을 지원함.
5. 교사가 최종 판단과 수정 권한을 유지함.

---

## 5.3 평가 및 피드백

### 평가 방식

* 학생의 평가 수준은 교사가 직접 입력함.
* AI는 평가 결과를 재판정하지 않음.
* AI는 입력된 수준과 평가계획을 문장으로 변환함.

### 피드백 제공

* 평가계획과 생성 문장의 연결 표시
* 수준 불일치 가능성 경고
* 과장 표현 경고
* 입력 근거 외 표현 경고
* 중복 문장 표시
* 바이트 수 표시
* 금지 내용 표시

### 데이터 활용

* 평가 입력 완료율 확인
* 평어 작성 완료율 확인
* 미입력 학생 확인
* 교사 수정 빈도 분석
* AI 생성 품질 개선
* 학생의 자동 등급 산출에는 사용하지 않음

* [ ] 같은 학급 완전 동일 문장 비율 1% 이하

### 업무 효율

* [ ] 교과 평어 작성 시간 50% 이상 단축
* [ ] 행동특성 작성 시간 50% 이상 단축
* [ ] 교사 수정 후 사용 가능 문장 비율 80% 이상
* [ ] 한 학급 전체 작성 완료 시간 절반 이상 단축

#### 파일럿 시간 측정 방법

실행 순서, 익명 측정표, 승인 게이트와 판정 절차는 `docs/PILOT_RUNBOOK.md`를 따름.

* 같은 교사가 동일한 규모의 학급과 유사한 평가계획을 대상으로 수기 작성 기준선과 기록샘 사용 시간을 각각 측정함.
* 교과 평어는 평가수준 입력 시작부터 25명 결과 검토·복사 완료까지, 행동특성은 관찰 사실 입력 시작부터 25명 결과 검토·복사 완료까지를 측정함.
* 로그인·초기 학급 생성 교육 시간, 의도적인 휴식, 네트워크 장애 대기 시간은 별도 기록하고 순수 작성 시간과 구분함.
* 시간 단축률은 `(수기 기준 시간 - 기록샘 사용 시간) / 수기 기준 시간 × 100`으로 계산함.
* 최소 3개 학급 또는 3명의 교사 표본에서 교과 평어·행동특성·전체 완료 시간을 각각 기록하고 중앙값이 50% 이상 단축될 때 목표 달성으로 판정함.
* 수정 후 실제 사용 가능 문장 수, AI 결과 수정 건수, 중단·재시도 횟수도 함께 기록하여 단순 속도 향상이 품질 저하로 이어지지 않았는지 확인함.

## v1.111 공용 문장 풀 무료 교정 운영 정책 (2026-08-23)

* 공용 문장 풀 교정은 실험실 계정, 과목, 예상 대상 수, `allowShared` 승인, 실제 적용 여부를 각각 확인한 경우에만 실행함. 다른 계정이 참조하는 풀은 공유 승인이 없으면 차단하고 계정 식별정보는 응답하지 않음.
* 교정은 의미를 바꾸지 않는 기계 교정본을 최신 공통 검수기로 다시 통과시킨 뒤 승인본을 먼저 확보하고, 문제 원문은 삭제하지 않고 `retired`로 보존함. 학생 평어·평가수준·학생·학급 데이터는 교정 대상에 포함하지 않음.
* 국어 최신 미통과 34개에 적용한 결과 7개 풀의 원문 34개를 `retired`로 보존함. 교정문은 모두 같은 풀에 이미 승인본으로 존재하여 신규 저장 없이 34개를 재사용했으며 OpenAI API 호출과 비용 증가는 없음.
* 적용 후 국어 15/15개 풀은 모두 사용 가능하고 현재 승인 문장은 212개임. 최신 main 코드와 운영 평가계획 지문을 정확히 연결한 읽기 전용 재감사에서 212/212개가 통과함. 최초 205/212 결과는 PR 병합 뒤 fast-forward되지 않은 이전 로컬 검수 코드를 사용한 감사 오류였으며 운영 문장 7개에는 문제가 없었음.
