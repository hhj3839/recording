## 0. 현재 제품 정책 및 개발 상태

### 확정된 정책 변경

* 교과 평가 관찰 메모는 사용하지 않으며 평가계획과 학생별 평가 수준을 근거로 교과 평어를 생성함.
* 행동특성은 영역별 입력 대신 학생당 하나의 `관찰 사실` 입력창을 사용함.
* AI 사실 검수와 별도 최종 확정은 사용하지 않음. 교과 평어와 행동특성 모두 바이트 수, 종결어미, 금지어, 맞춤법 자체 규칙, 반복 및 학급 내 중복률을 표시하고 교사가 화면에서 바로 수정함.
* 교과 평어 후보·문장 수·최대 바이트·작성 방향 설정은 사용하지 않으며 결과는 1개만 생성함.
* 교과 평어는 입력된 평가 영역마다 정확히 1문장을 작성하고, 각 문장은 50~60자를 권장하며 `함.`으로 끝냄. 48~49자와 61~62자는 교사 확인 경고로 제공하고 결과는 보존함.
* 행동특성은 학생별 특성을 4개 이상 입력해야 일괄 생성을 시작할 수 있음.
* 교과 평어와 행동특성 일괄 생성은 서버 백그라운드 작업으로 실행되며 페이지를 닫아도 계속 진행하고 결과를 저장함.
* 교과 평어는 실패 영역만 최대 3회 추가 재생성하고, 행동특성도 실패 학생만 실제 바이트 진단을 포함해 최대 3회 개별 재조정함. 실제 AI 호출 시도마다 월 사용량에 기록함.
* 각 평가 영역의 후보는 1개만 생성하고 첫 요청에서 통과한 영역은 즉시 저장하며, 누락·형식 실패 영역만 보완 생성함.
* 나이스 자동입력 매크로는 웹 브라우저 보안 제약으로 현재 개발 범위에서 보류함. 교과 평어와 행동특성 화면에서 번호순 본문 복사를 제공함.
* 전체 결과 공유, Excel·CSV 내보내기, Google Sheets 생성 기능은 코드는 보존하되 현재 사용자 화면에서는 숨김 처리함.
* 교사 파일럿 측정 화면과 API는 제품에서 제거하고 실제 파일럿은 별도 운영 절차로 수행함.

### 2026.07.27 PRD 대비 개발 점검

* MVP 1과 MVP 2의 핵심 사용자 흐름은 구현 및 자동 테스트를 완료함.
* 교과 평어의 2026-07-27 최초 실측 스냅샷은 215/225건 저장(95.56%)이었음. 2026-08-12 생성 직전 스냅샷에서 214/225건과 누락 11건을 확인한 뒤 그 11건만 제한 생성하여 현재 225/225건 저장과 누락 0건을 확인함. 최근 생성 11건은 영역 수·50~60자·`함.` 종결 엄격 형식 11/11건을 통과했으며, 전체 225건의 최신 의미 일치 품질 재감사는 아직 수행하지 않음.
* 행동특성은 25/25명 저장됐고 최신 전수 감사에서 23/25명(92%)이 엄격 기준을 통과함. 남은 120번·125번은 길이 외 검사를 통과하며 목표 95%에는 1명 부족함.
* `confirmed`, `confirmed_at` 필드는 과거 데이터 호환을 위해 보존하지만 현재 사용자 화면에서는 별도 최종 확정 절차를 제공하지 않음.
* 전체 결과 공유·CSV·Google Sheets 관련 구현은 `SHOW_EXPORT_RESULTS = false`로 비노출 상태를 유지함.
* 운영 Supabase `recording` 프로젝트는 Free 요금제를 유지함. 2026-08-11 확인 결과 자동 백업과 PITR은 제공되지 않으며, 프로젝트 리전은 Oceania(Sydney), `ap-southeast-2`임.
* 한 교사 계정의 핵심 보관 단위는 학년도·학기별 학급 1개와 그 학급에 연결된 학생·평가·생성 결과 1세트임. 새 학기는 새 학급으로 생성하며 기존 학기 자료는 명시적으로 삭제하기 전까지 유지함.
* 실제 교사 파일럿 및 성공 지표는 아직 운영 확인이 필요함.
* GitHub `main`과 Vercel Production 자동 배포 연동을 확인함.

## 1.2 개발 배경

### 교실에서 마주한 문제점

초등학교 교사는 학기말마다 학생별 교과학습발달상황과 행동특성 및 발달상황을 작성해야 함. 학생 수가 많고 평가 항목도 다양하여 평가계획과 학생별 평가 결과를 일일이 확인하면서 서로 다른 문장을 작성하는 데 많은 시간이 소요됨.

교과 평어를 작성하려면 다음 내용을 함께 고려해야 함.

* 과목
* 단원
* 평가목표
* 평가 영역
* 평가 유형
* 평가 관점
* 학생의 상·중·하 평가 수준
* 수준별 평가 기준
* 평가상의 유의점

그러나 실제 작성 과정에서는 다음과 같은 어려움이 발생함.

1. 과정중심평가 계획과 학생별 평가 결과를 연결하기 어려움.
2. 같은 평가 수준의 학생에게 유사한 문장을 반복하게 됨.
3. 평가 항목이 많아질수록 학생별 평어 작성 시간이 크게 증가함.
4. 행동특성 작성 시 학생의 여러 특성을 자연스럽게 연결하기 어려움.
5. 입력하지 않은 사실이 문장에 포함되지 않도록 반복 검토해야 함.
6. 모든 문장의 맞춤법, 종결어미, 바이트 수를 직접 확인해야 함.
7. 여러 교사가 각자 다른 방식으로 AI를 사용하여 결과의 일관성이 떨어짐.
8. 학생 개인정보를 일반 생성형 AI 서비스에 직접 입력할 가능성이 있음.

### 기대 효과

* 교과 평어와 행동특성 초안 작성 시간 50% 이상 단축
* 과정중심평가 계획과 교과 평어의 일치도 향상
* 학생별 문장 중복 감소
* 관찰 사실에 근거한 구체적인 행동특성 작성
* 바이트 수와 종결어미 자동 검수
* 교사가 최종 검토와 수정에 집중할 수 있는 환경 제공
* 여러 학교 교사가 동일한 방식으로 안전하게 사용할 수 있는 서비스 구축

### 기능 3. 학생 명단 관리

**설명:**
학생 이름과 번호를 등록하고 학생별 평가 및 행동특성 데이터를 연결함.

**사용 시나리오:**

1. 교사가 엑셀이나 한글 표에서 번호와 이름 두 열을 복사해 붙여넣음.
2. 앱이 번호와 이름을 자동으로 인식함.
3. 교사가 누락되거나 잘못된 정보를 수정함.
4. 학생별 평가 입력 화면이 자동 생성됨.

**주요 기능:**

* `번호 이름` 형식의 여러 줄 명단 붙여넣기와 자동 인식
* 학생 정보 수정
* 전입생 추가
* 전출생 비활성화
* 학생 순서 변경
* 다른 학급으로 학생 명단을 복사하는 기능은 제공하지 않음

**필수 학생 정보:**

* 학생 내부 식별번호
* 번호
* 이름
* 학급

**우선순위:** 상

### 기능 4. 일반 교과 평가계획 표 붙여넣기

**설명:**
교사가 엑셀이나 한글 표에서 정해진 10개 열을 복사해 붙여넣으면 앱이 각 행을 하나의 평가 항목으로 인식해 저장함. 파일 업로드는 제공하지 않음.

### 표준 열 구조

| 열 이름     | 설명                | 필수 여부 |
| -------- | ----------------- | ----- |
| 과목       | 국어, 사회, 수학, 과학 등  | 필수    |
| 단원       | 평가 단원명            | 필수    |
| 평가목표     | 학생이 도달해야 할 목표     | 필수    |
| 영역       | 교과 평가 영역          | 필수    |
| 평가 유형    | 서술형, 구술, 관찰, 실기 등 | 선택    |

| 상        | 상 수준 평가 기준        | 필수    |
| 중        | 중 수준 평가 기준        | 필수    |
| 하        | 하 수준 평가 기준        | 필수    |
| 평가상의 유의점 | 평가 시 고려 사항        | 선택    |

**사용 시나리오:**

1. 교사가 학년도, 학기, 학년을 선택함.
2. 평가계획의 10개 열을 복사해 입력창에 붙여넣음.
3. 앱이 탭으로 구분된 열과 행을 자동으로 인식함.
4. 평가 항목 미리보기를 제공함.
5. 오류가 있는 행을 표시함.
6. 교사가 수정하거나 제외함.
7. 평가계획을 저장함.

### 기능 8. 과목별 교과 평어 생성

**설명:**
과목별 AI 평어 생성 버튼으로 평가수준이 입력된 전체 학생의 선택 과목 평어를 서버 백그라운드 작업으로 생성함.

**사용 시나리오:**

1. 교사가 학생별 평가 수준을 저장함.
2. 교과 평어 화면에서 AI 평어 생성을 실행함.
3. 페이지를 이동하거나 닫아도 서버에서 작업을 계속함.
4. 생성 결과를 학생·과목별로 저장함.
5. 교사가 과목 탭을 선택해 번호·이름·평어 표를 검토함.

**안전 장치:**

* 미입력·평가 예정·미응시 항목 구분
* 입력된 각 평가 영역마다 정확히 한 문장 생성
* 영역별 50~60자 권장 및 `함.` 종결 검사
* 48~49자와 61~62자는 차단하지 않고 길이 확인 경고 표시
* 누락·중복된 평가 근거 검사
* 학급 내 유사 표현과 중복률 표시
* 성공한 영역 문장은 즉시 영역 단위로 저장
* 실패 영역만 동일 저비용 모델로 최대 3회 추가 재시도
* 세 번의 시도 후 실패한 영역은 `확인 필요`로 표시하고 다른 성공 문장은 유지
* 다음 요청에서는 같은 평가 근거로 이미 저장된 성공 영역을 다시 생성하지 않음
* 페이지 이동 후 작업 상태와 저장 결과 복원

**우선순위:** 상

### 기능 10. 행동특성 입력

**설명:**
학생 이름 옆의 단일 `관찰 사실` 입력창에 실제로 관찰한 특성과 변화 모습을 자유롭게 입력함.

### 입력 가능한 특성 영역

* 학습 태도
* 교우관계
* 책임감
* 생활 습관
* 의사소통
* 협력
* 자기관리
* 성장 모습
* 특별히 강조할 점

**입력 예시:**

```text
학습 태도: 수업에 성실하게 참여하며 궁금한 내용을 질문함
교우관계: 친구의 이야기를 잘 듣고 갈등이 생기면 대화로 해결하려고 함
책임감: 맡은 역할을 끝까지 수행함
생활 습관: 준비물을 스스로 점검하는 습관이 형성되고 있음
성장 모습: 발표를 어려워했으나 최근에는 모둠 앞에서 자신의 생각을 말함
특별히 강조할 점: 배려심, 꾸준함
```

**입력 방식:**

* 학생당 단일 자유 메모 입력
* 8개 영역의 강점·성장 지원 참고자료 제공
* 참고 표현을 클릭하여 현재 학생 입력창에 추가
* 학생별 직접 수정

**우선순위:** 상

### 기능 11. 행동특성 및 발달상황 생성

**설명:**
교사가 입력한 학생 특성 4~5가지를 바탕으로 행동특성 및 발달상황 초안을 생성함.

### 작성 원칙

1. 교사가 입력한 학습 태도, 교우관계, 책임감, 생활 습관, 의사소통, 협력, 자기관리, 성장 모습을 중심으로 작성함.
2. 학생의 장점과 발전 가능성이 구체적으로 드러나도록 작성함.
3. 부정적 표현은 직접 사용하지 않고 변화와 성장 중심으로 순화함.
4. 활동을 단순 나열하지 않고 행동의 특징, 과정, 변화가 나타나도록 작성함.
5. 모든 문장을 `음` 또는 `임`으로 끝냄.
6. 한글 맞춤법과 띄어쓰기를 준수함.
7. UTF-8 기준 500바이트 이상 550바이트 이하로 작성함.
8. 대회 실적, 수상 실적, 사교육, 공인시험, 특정 기관명, 부모의 직업이나 사회경제적 배경을 포함하지 않음.
9. 입력된 사실을 과장하거나 새로운 사실을 추가하지 않음.
10. 학생이 여러 명이면 학생별로 구분하여 모두 작성함.

**우선순위:** 상

---

### 기능 12. 행동특성 자동 검수

**설명:**
행동특성 생성 결과가 작성 원칙에 맞는지 자동 검사함.

**검수 항목:**

* UTF-8 기준 500~550바이트
* 모든 문장 종결어미가 `음` 또는 `임`인지
* 동일 표현이 반복되는지
* 학생의 변화와 성장 모습이 포함되었는지
* 금지 내용이 포함되었는지
* 부정적이거나 단정적인 표현이 있는지
* 맞춤법과 띄어쓰기 오류가 있는지

**검수 결과 예시:**

```text
바이트 수: 537바이트
종결어미: 정상
성장 모습: 포함
반복 표현: 없음
금지 내용: 없음
```

**현재 정책:** 별도의 AI 사실 검수는 사용하지 않으며 위 항목 중 의미 추론이 필요한 `입력 근거 외 표현` 검사는 제공하지 않음.

**우선순위:** 상

### 기능 13. 행동특성 일괄 생성

**설명:**
학생별 특성이 입력된 학급 전체 학생의 행동특성을 한 번에 생성함.

**주요 기능:**

* 특성을 입력한 학생을 생성 대상에 자동 포함
* 입력 특성 부족 학생 경고
* 일괄 생성
* 학생별 바이트 수 표시
* 반복 문장 검사
* 학생별 수정
* 500~550바이트 이탈 결과의 분량 경고와 직접 수정

**제한 조건:**

* 관찰 사실이 없는 학생은 생성 대상에서 제외
* 학생별 특성이 4개 미만이면 일괄 생성 전에 경고
* 생성 전 개인정보 및 금지 내용 검사

**우선순위:** 상

# 5. 교육적 고려사항

## 5.1 교육과정 연계

### 대상

* 초등학교 1~6학년
* 일반 교과목
* 행동특성 및 발달상황

### 연계 정보

* 과목
* 단원
* 평가목표
* 평가 영역
* 평가 유형
* 평가 관점
* 수준별 평가 기준
* 평가상의 유의점
* 학생별 평가 결과

### 교육적 원칙

* AI가 평가 수준을 결정하지 않음.
* 교사가 입력한 평가 결과만 문장으로 변환함.
* 평가계획을 벗어난 내용을 생성하지 않음.
* 학생 간 비교나 서열화를 하지 않음.
* 낮은 평가 수준을 낙인찍는 표현으로 작성하지 않음.
* 학생의 실제 수행과 성장 모습을 중심으로 작성함.

---

## 5.2 학습 및 평가 지원 목표

1. 과정중심평가 계획과 생활기록부 평어를 일관되게 연결함.
2. 학생별 평가 결과를 구체적이고 자연스러운 문장으로 표현함.
3. 교사의 반복적인 문장 작성 부담을 줄임.
4. 학생의 강점과 성장 가능성이 드러나는 기록을 지원함.
5. 교사가 최종 판단과 수정 권한을 유지함.

---

## 5.3 평가 및 피드백

### 평가 방식

* 학생의 평가 수준은 교사가 직접 입력함.
* AI는 평가 결과를 재판정하지 않음.
* AI는 입력된 수준과 평가계획을 문장으로 변환함.

### 피드백 제공

* 평가계획과 생성 문장의 연결 표시
* 수준 불일치 가능성 경고
* 과장 표현 경고
* 입력 근거 외 표현 경고
* 중복 문장 표시
* 바이트 수 표시
* 금지 내용 표시

### 데이터 활용

* 평가 입력 완료율 확인
* 평어 작성 완료율 확인
* 미입력 학생 확인
* 교사 수정 빈도 분석
* AI 생성 품질 개선
* 학생의 자동 등급 산출에는 사용하지 않음

* [ ] 같은 학급 완전 동일 문장 비율 1% 이하

### 업무 효율

* [ ] 교과 평어 작성 시간 50% 이상 단축
* [ ] 행동특성 작성 시간 50% 이상 단축
* [ ] 교사 수정 후 사용 가능 문장 비율 80% 이상
* [ ] 한 학급 전체 작성 완료 시간 절반 이상 단축

#### 파일럿 시간 측정 방법

실행 순서, 익명 측정표, 승인 게이트와 판정 절차는 `docs/PILOT_RUNBOOK.md`를 따름.

* 같은 교사가 동일한 규모의 학급과 유사한 평가계획을 대상으로 수기 작성 기준선과 기록샘 사용 시간을 각각 측정함.
* 교과 평어는 평가수준 입력 시작부터 25명 결과 검토·복사 완료까지, 행동특성은 관찰 사실 입력 시작부터 25명 결과 검토·복사 완료까지를 측정함.
* 로그인·초기 학급 생성 교육 시간, 의도적인 휴식, 네트워크 장애 대기 시간은 별도 기록하고 순수 작성 시간과 구분함.
* 시간 단축률은 `(수기 기준 시간 - 기록샘 사용 시간) / 수기 기준 시간 × 100`으로 계산함.
* 최소 3개 학급 또는 3명의 교사 표본에서 교과 평어·행동특성·전체 완료 시간을 각각 기록하고 중앙값이 50% 이상 단축될 때 목표 달성으로 판정함.
* 수정 후 실제 사용 가능 문장 수, AI 결과 수정 건수, 중단·재시도 횟수도 함께 기록하여 단순 속도 향상이 품질 저하로 이어지지 않았는지 확인함.

# 부록 B. 평가계획 10열 붙여넣기 형식

| 과목 | 단원 | 평가목표 | 영역 | 평가 유형 | 평가 관점 | 상 | 중 | 하 | 평가상의 유의점 |
| -- | -- | ---- | -- | ----- | ----- | - | - | - | -------- |

### 작성 규칙

1. 과목부터 평가상의 유의점까지 10개 열 순서를 유지함.
2. 한 행에는 하나의 평가 항목만 입력함.
3. 각 열은 탭으로 구분하여 붙여넣음.
4. 상·중·하 기준을 모두 입력함.
5. 여러 평가 관점은 `/` 또는 줄바꿈으로 구분함.
6. 여러 평가 유형은 쉼표로 구분함.
7. 평가계획에는 학생 개인정보를 입력하지 않음.

# 부록 C. API 교과 평어 생성 원칙

1. 과목·단원·평가목표·영역을 반영함.
2. 평가 관점과 선택 수준 기준을 중심으로 작성함.
3. 평가상의 유의점은 문장에 직접 복사하지 않고 생성 제한 조건으로 활용함.
4. 상 수준을 받은 학생에게만 과도하게 우수한 표현을 사용하지 않음.
5. 중 수준은 기본 성취가 드러나도록 작성함.
6. 하 수준은 부정적 표현보다 수행 과정과 성장 가능성을 중심으로 작성함.
7. 평가계획과 입력된 평가 수준에 없는 사실은 포함하지 않음.
8. 입력되지 않은 사실은 생성하지 않음.
9. 학생 간 비교 표현을 사용하지 않음.
10. 교사가 반드시 검토하고 필요한 경우 수정함.

# 부록 D. 행동특성 생성 프롬프트 원칙

```text
너는 대한민국 초등학교 담임교사이다.
학생의 행동특성 및 발달상황을 작성한다.

작성 원칙
1. 교사가 입력한 관찰 사실만 활용한다.
2. 학습 태도, 교우관계, 책임감, 생활 습관,
   의사소통, 협력, 자기관리, 성장 모습을 중심으로 작성한다.
3. 장점과 발전 가능성이 구체적으로 드러나게 작성한다.
4. 부정적인 표현은 직접 쓰지 않고 변화와 성장 중심으로 순화한다.
5. 활동을 단순 나열하지 않고 행동의 특징, 과정, 변화를 연결한다.
6. 모든 문장은 음 또는 임으로 끝낸다.
7. UTF-8 기준 500바이트 이상 550바이트 이하로 작성한다.
8. 대회 실적, 수상 실적, 사교육, 공인시험, 특정 기관명,
   부모 직업, 사회경제적 배경을 포함하지 않는다.
9. 입력된 사실을 과장하거나 새로운 사실을 추가하지 않는다.
10. 학생이 여러 명이면 학생별로 구분한다.

출력 전 검수
- 500~550바이트인지 확인한다.
- 모든 문장이 음 또는 임으로 끝나는지 확인한다.
- 같은 표현이 반복되지 않았는지 확인한다.
- 구체적인 변화와 성장 모습이 포함되었는지 확인한다.
- 금지 내용이 없는지 확인한다.
```
