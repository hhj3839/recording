# 로그인 로딩 복구 수정 — 2026-11-03

- 확인한 결함: 로그인 폼 submit에서 fetch 또는 response.json 예외를 처리하지 않아 setBusy(false)에 도달하지 못했다. 네트워크 오류나 프록시의 HTML 응답이면 처리 중 표시와 비활성 버튼이 계속 남았다. 요청과 응답 본문에 시간 제한도 없었다.
- 당시 운영 지연의 직접 원인: 확정하지 못했다. 이전 운영 확인에서는 지연 후 같은 탭의 실험실 대시보드가 정상 표시됐다. 이번 수정은 재현 가능한 무한 로딩 경로를 제거하며 Supabase 지연 원인을 확정한 것으로 해석하지 않는다.
- 수정: try/catch/finally로 실패 안내와 버튼 복구 보장, 응답 본문까지 포함한 20초 AbortController 제한, 동시 제출 방지, 처리 중 모드 전환 차단, 성공 응답 형태 확인. 로그인 실패 제한과 인증·쿠키 정책은 유지한다.
- 재현: 실제 submit 함수 본문을 실행하는 검사 7개 중 수정 전 5개 실패, 수정 후 7개 통과. 네트워크 오류·HTML 504·null 응답·본문 지연·중복 제출·401 안내·메일 요청 성공을 확인한다. 실제 계정 비밀번호나 운영 인증 요청은 사용하지 않았다.
- 검증: 타입 검사 및 변경 파일 린트 통과. 배포 전 로컬 수정 기록이다.
- 제한: 브라우저 요청 중단은 이미 서버에 전달된 로그인/메일 요청을 취소하지 않는다. 자동 재시도를 하지 않고 사용자가 다시 시도할 수 있도록 한다.
