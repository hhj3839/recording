# 기록샘 교육기관 보안성 자체 점검

**점검일:** 2026-08-17

**대상:** `giroksam-recording.vercel.app`, Supabase 운영 프로젝트, GitHub CI

**성격:** 개발자 자체 기술 점검이며 교육기관의 공식 보안성 검토나 법률 자문을 대체하지 않음

## 결론

친구 교사 중심의 제한된 비공개 파일럿을 위한 기본 보안 통제는 갖추었음. 학생 이름과 평가자료를 처리하므로 학교 또는 교육기관의 정식 운영 승인을 받은 서비스로 판정할 수는 없음. 전체 플랫폼 복원 리허설, 처리위탁·국외이전 고지 확정, 접근 감사 로그와 기관 담당자의 보안 검토가 정식 운영 전 필수임.

## 통과한 항목

- Supabase Auth 이메일 로그인과 이메일 인증 흐름
- 비밀번호 최소 정책과 5회 실패 시 15분 로그인 제한
- 30분 미사용 시 로그아웃
- 액세스·갱신 토큰을 `HttpOnly`, 운영 `Secure`, `SameSite=Lax` 쿠키로 보관
- 모든 주요 앱 조회·수정·삭제에서 사용자 ID와 학급 ID를 함께 검사
- 타 학급 식별자 조회·수정, 작업 서명 위조, 삭제 확인 우회 자동 차단
- 비로그인 사용자의 민감 API 접근 차단
- OpenAI 요청에서 학생 이름과 번호 제외
- 서비스 역할 키와 OpenAI 키를 브라우저에 노출하지 않음
- 2026-08-20 재검증 기준 추적 파일 비밀정보 검사 195개 파일 통과
- 잠금파일 683개 레지스트리 패키지의 SHA-512 무결성 확인
- GitHub Actions 외부 액션 5개를 전체 커밋 SHA로 고정
- 운영 의존성 감사에서 알려진 취약점 0건
- CSP, 클릭재킹 차단, MIME 스니핑 차단, Referrer·Permissions·교차 출처 보안 헤더를 모든 경로에 적용
- 운영 데이터베이스의 `public` 18개 테이블 전체 RLS 활성
- 일반 `anon/authenticated` 역할에 허용 정책이 없어 기본 접근 거부

## 주요 위험과 조치

### 1. 전체 재해복구 미검증 — 높음

핵심 앱 데이터의 로컬 복원 이력은 있으나 Auth 로그인과 플랫폼 설정을 포함한 임시 Supabase 프로젝트 복원은 미실행임. Storage는 현재 비어 있지만 향후 파일을 사용하면 데이터베이스와 별도로 객체를 백업해야 함. `SUPABASE_PLATFORM_RESTORE_RUNBOOK.md` 절차로 임시 프로젝트 리허설을 수행해야 함.

### 2. 서비스 역할 키 의존 — 중간

서버 데이터 계층이 서비스 역할 키를 사용하여 RLS를 우회함. 현재 API의 `owner_id + class_id` 검사와 자동 권한 테스트가 실질적인 격리 경계임. 서비스 키는 서버에만 두고 정기 회전하며, 새 API가 추가될 때 외부 학급 ID 테스트를 필수화해야 함. 장기적으로는 사용자 JWT 기반 데이터 접근 또는 소유권을 강제하는 제한 RPC로 축소하는 방안을 검토함.

### 3. 접근 감사 로그 부족 — 중간

AI 사용량과 기록 수정 이력은 있으나 로그인 성공, 학급 조회, 개인정보 다운로드·삭제, 관리자성 작업을 한곳에서 추적하는 학교 단위 감사 로그는 없음. 소수 비공개 파일럿에서는 운영 기록으로 보완할 수 있지만 기관 운영 전에는 비식별 감사 로그와 보존 기간을 정해야 함.

### 4. 백업 자동화 부재 — 중간

Free 요금제에는 관리형 자동 백업과 PITR이 없음. 월 1회 수동 암호화 백업, 복원 시험 일정, 보관 위치와 담당자를 확정하거나 Pro 이상으로 전환해야 함. 이번 점검에서 문서에 기록된 과거 암호화 백업 파일의 현재 위치와 무결성은 독립적으로 재확인하지 못함.

### 5. 개인정보·계약 검토 미완료 — 높음

개인정보 처리방침 초안은 있으나 Supabase, Vercel, OpenAI의 정확한 법인명, 처리 국가, 이전 시점·방법, 보유 기간, 거부 방법과 학교 승인 절차를 확정해야 함. 학생 실명·평가정보 사용 전 학교 개인정보 보호 담당자의 검토가 필요함.

## 운영 허용 범위

- 허용: 개발자와 사전 동의한 소수 교사의 비공개 파일럿, 최소 데이터, 교사 최종 검토 필수
- 조건부: 실제 학생 실명 사용은 학교 내부 승인, 안내, 최소 보유기간, 삭제 절차를 확인한 경우
- 미허용: 교육기관 공식 서비스라고 홍보, 다수 학교 공개 가입, 관리자 감사 없이 대규모 운영, 검증되지 않은 백업을 복구 가능하다고 표시
