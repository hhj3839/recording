## 실행 순서

기존 1번의 명시적 재개 UX는 구현·격리 회귀·배포와 제한된 운영 검증까지 완료했다. 전체 플랫폼 복원 리허설을 다음 1번으로 올린다. 실제 운영 생성 완료 검증과 배치 도중 장애의 멱등성은 아래 3번에 별도로 남긴다. 성능 표본 확대는 4번을 유지한다.

| 순서 | 우선도 | 과제와 근거 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | P1 | 최신 백업 기준 전체 플랫폼 복원 리허설. 기존 검증은 로컬 논리 데이터 복원 범위다. | 격리 환경에서 DB·Auth·Storage 실제 파일·설정을 복원하고 로그인, 학급 권한, 결과 조회를 확인한다. 백업 시점·누락 범위·복구 시간을 기록한다. |
| 2 | P1 | 실제 교사 파일럿. 생성 완료와 교육적 품질은 별개이며 의미·시간 지표는 아직 실측되지 않았다. 모집은 기술 작업과 병행할 수 있다. | 수준 의미 일치 95%, 입력 밖 사실 3% 이하, 수정 후 사용 가능률 80%, 작성 시간 50% 단축 목표를 교사 표본에서 측정한다. 달성 여부·표본·실패 사례를 기록하고 미달 원인을 개선 과제로 전환한다. |
| 3 | P2 | 재개 기능의 실행 환경 통합·배치 도중 장애 검증. 현재 재개 성공은 격리 모의 환경, 운영은 조회·거부 경로까지만 확인했다. | 운영과 동등한 격리 환경에서 서명된 후속 호출·실행시간 초과·재개 후 완료를 검증한다. 외부 응답 직후/저장 직후/진행 위치 기록 전 장애를 주입해 중복 비용·결과 보존을 확인하고 필요 시 체크포인트·멱등성 개선을 설계한다. 실제 운영 작업 검증은 대상과 비용·변경 범위를 명확히 정해 진행한다. 중복 실행·손실이 재현되면 P1로 상향한다. |
| 4 | P2 | 리전 최적화 후 성능 표본 확대와 실제 브라우저 전환 검증. 서버 지연은 줄었지만 로그인 1회·조회 2회로는 꼬리 지연을 판단할 수 없다. | 계정·시간대·첫 방문/반복 방문별 제한된 표본 계획을 정하고 API와 운영 브라우저의 로그인 클릭→대시보드 표시 완료를 분리 측정한다. 인증·학급·본문·클라이언트 대기를 구분하고 간헐적 학급 조회 215~275ms를 재확인한다. 충분한 표본에서 중앙값/p95와 목표를 정하며, 새 기능 저하가 재현되면 P1로 상향한다. |
| 5 | P2 | 의존성 경고와 CI·로컬 검사 범위 정리. 최근 push의 moderate 경고 1건은 상세 재감사가 남아 있다. | 현재 advisory와 실제 영향 경로를 확인해 대응 여부를 결정한다. 임시 산출물만 제외하고 실제 소스는 검사해 CI와 로컬 결과를 일치시킨다. 영향이 큰 취약점이면 우선도를 상향한다. |
| 6 | P2 | 작업 폴더와 잔여 변경 정리. 기본 폴더의 오래된 미커밋 변경과 최신 배포용 작업 폴더가 분리돼 있다. | 최신 main과 기능별로 대조해 반영됨/추가 통합 필요/보존 자료로 분류한다. 원본을 보존하고 필요한 변경만 별도 PR로 검증한다. |
| 7 | P2 | 평어 풀 수량·연결 이력 대조. 이전 실험실 UI의 81/81·1,668문장은 과거 1,620/1,621 기록과 다르다. | 동일 계정·학급·풀 버전·시점 기준 읽기 전용 대조로 차이를 설명한다. 이번 리전 작업에서 수량을 다시 확인한 것은 아니며, 차이를 자동 생성 재발이나 품질 향상으로 추정하지 않는다. |

P1은 안정성·복구·제품 검증에 먼저 필요한 작업, P2는 후속 성능 검증·유지보수·정합성 작업이다. 현재 재현된 P0 장애가 있다는 뜻은 아니다.

## 검증 범위와 한계

- 자동 시작 운영 검사는 화면 이동·새로고침 및 입력값 비교였다. 운영에 대기/진행 작업을 인위적으로 만들거나 DB 전수 불변을 검사한 것은 아니다.
- 후속 운영 로그인 API와 인증된 조회는 실제 계정으로 측정해 정상 응답을 확인했다. 실제 브라우저 클릭부터 표시 완료까지의 운영 시간은 아직 별도 과제다.
- 최신 브라우저 회귀 18개는 실제 화면 컴포넌트와 모의 API를 사용한 격리 검사다. 운영 DB까지의 브라우저 통합 검사로 확대 해석하지 않는다.
- 재개 운영 검증은 미인증307→로그인, 실험실 로그인200, 세 상태 GET200, 없는 작업404다. 운영의 실제 재개 성공·유료 생성은 검사하지 않았다. 현재 미완료 배치는 재시도될 수 있고 외부 AI 호출까지 exactly-once를 보장하지 않는다.
- 리전 변경 전후 총 11요청씩 모두 200이었다. DB 서비스 처리 시간과 네트워크 왕복을 함께 해석했으며 upstream 지표를 순수 SQL 실행시간이라고 보지 않는다.
- 전체 테스트 217개·관련 권한/로그인/계측 23개·브라우저 11개와 CI가 리전 배포에서 통과했다.
