## 실제 AI 부하 테스트

최신 구조에서 5명·1과목 5/5, 25명·1과목 25/25를 통과한 뒤 25명·9과목 225건을 실행함. 최종 215건 성공, 10건 실패로 목표 성공률 95%를 넘었으며 저장 결과의 엄격 형식 통과율은 100%였음.

다만 품질 표본에서 `함함.`, `하고함.`, `감함.`처럼 기계적으로 결합된 종결 표현이 발견되어 해당 실측을 최종 품질 통과로 판정하지 않음. 완성 서술어를 제한하고 학생별 고정 응답 슬롯을 사용하는 새 스키마를 배포했으나, 재검증 시 OpenAI 프로젝트에서 `insufficient_quota`가 반환되어 실제 품질 재검증은 결제 한도 복구 후 진행해야 함.

### 발견된 문제와 조치

- 60초 함수 제한으로 재시도 완료 전 종료 → 실행 제한을 300초로 확대
- 취소 상태가 실행 중 함수에 의해 덮어써짐 → 저장 전·완료 전 취소 상태 재확인
- 성공 건수만 사용량에 기록 → 실제 API 호출 시도마다 기록
- JSON 응답 잘림 → 추론 비활성화, 출력 한도 확대, JSON Schema Structured Outputs 적용
- 과거 5명 배치의 복합 실패로 3명까지 축소했으나 5명 배치로 복원함. 최신 구조는 영역별 후보 1개를 생성하고 통과한 영역을 즉시 저장한 채 실패 영역만 최대 두 번 추가 보완함
- API 호출 누적 → 교사별 월 한도를 150회로 축소
- 학생 ID 반복 출력 → 학생별 고정 결과 슬롯과 허용 ID·과목·영역을 스키마에서 제한
- 부자연스러운 `함.` 결합 → 허용된 완성 서술어만 구조적으로 선택하고 어색한 종결 패턴 저장 차단
- `insufficient_quota` 발생 → 비재시도 오류로 분류해 같은 배치의 불필요한 추가 호출 중단

## 평가 수준 의미 일치 표본

사회 교과에서 30문장을 평가 영역·수준·기준과 대조함.

- 직접 일치: 27문장
- 교사 확인 필요: 3문장
- 명백한 수준 불일치: 0문장
- 보수적 의미 일치율: 90%

교사 확인 필요 사례는 평가기준에 명시되지 않은 `자신 있게`, `의미를 파악함`, `모둠원과 협력하여`와 같은 태도·과정 표현이 추가된 경우임. 목표 95%에 미달하므로 실제 파일럿 전 의미 일치 표본을 추가하고 프롬프트를 더 제한해야 함.

## 결론

화면·권한·백그라운드 작업과 엄격 형식 검사는 작동하며 최신 225건 생성 성공률은 95.56%로 수치 목표를 통과함. 그러나 종결 표현 품질 문제가 발견되어 새 고정 슬롯·제한 서술어 구조로 변경했으며, OpenAI API 결제 한도 복구 후 5명·25명 게이트와 225건 품질 검사를 다시 통과해야 운영 완료로 판정함.

행동특성도 10명 배치에서 5명 배치로 낮춰 대량 응답 잘림과 단일 요청 실패 범위를 줄였음. 실패 학생은 실제 바이트와 검수 사유를 포함해 한 명씩 재조정하며, 470~580바이트 범위에서 나머지 검수를 통과한 결과는 폐기하지 않고 화면에 보존함. 이 최신 구조의 25명 실제 생성 성공률은 별도로 측정해야 함.

운영 보안 스모크 테스트는 약한 회원가입 비밀번호, 누락되거나 잘못된 학교·학급 정보, 비로그인 민감 API 접근, 다른 학급 식별자 사용, 평가수준이 연결된 과목명 변경, 작업 실행 서명 위조와 삭제 확인 문구 우회를 자동 차단하는지 확인함.
