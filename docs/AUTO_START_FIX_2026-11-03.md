# 상태 조회에 의한 자동 실행 수정

현재 상태: PR #273 병합 및 운영 배포 완료. [배포·운영 검증 결과](AUTO_START_DEPLOYMENT_2026-11-03.md)를 우선한다. 아래 미배포 표현은 수정 직후의 기록이다.

- 원인: 교과평어·행동특성 GET과 평어 풀 목록/개별 작업 GET이 queued/running 작업을 조회하면 실행기를 호출했다. 화면 진입·새로고침·주기적 조회만으로 기존 작업이 재개될 수 있었다. 신규 작업이 자동 생성되는 경로를 재현한 것은 아니다.
- 재현: 실제 API 모듈을 실행하고 DB와 네트워크를 모의 구현했다. 수정 전 상태 조회 23개 검사 중 10개에서 runner 호출과 waitUntil 등록을 확인했다. 운영 데이터 및 유료 API 호출은 사용하지 않았다.
- 수정: 세 API의 GET에서 실행기 호출을 제거했다. 명시적 POST의 시작/재개 및 실행기의 다음 배치 연결은 유지한다. 이미 실행 중인 서버 작업이나 별도 스케줄러를 취소하는 변경은 아니다. 조회가 중단된 작업을 복구해 주던 동작은 제거된다.
- 회귀: 조회 23개와 명시적 POST 재개 2개를 CI에 포함했다. 기존 자동 재개를 요구하던 소스 검사도 새 정책에 맞췄다.
- 검증: 전체 빌드 및 기본 테스트 217개, 추가 상태 조회/로딩/저장 실패 검사 34개, 타입 검사 통과. 임시 .local-reports 자료를 제외한 린트 오류 0, 기존 페이지 이동 경고 2개. 기본 pnpm lint는 기존 임시 패키지 자료의 오류 54개로 실패하므로 구분한다.
- 범위: 로컬 수정이며 미배포. 사용자 운영 화면에서 관찰했던 현상이 이 경로와 동일한지는 배포 후 확인이 필요하다. 기존 복사·붙여넣기 검증 보고서의 미커밋 수정은 보존했다.
