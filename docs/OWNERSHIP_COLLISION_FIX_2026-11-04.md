# 이메일 충돌 시 소유권 보존 수정 — 2026-11-04

## 재현과 수정

실제 data-scope·학급 POST·DB 요청 코드를 상태를 보관하는 모의 PostgREST에 연결했다. 수정 전 신규 8개 검사 중 7개가 실패했다. NULL/다른 UUID 소유 교사·학급이 이메일 충돌 upsert로 새 계정에 연결되고, 정상 소유자의 기존 학급도 학교명·생성 시각이 덮어써졌다.

교사 준비와 학급 생성은 이제 `resolution=ignore-duplicates`로 충돌 행을 보존한다. DB의 원자적 충돌 처리 후 삽입 결과 또는 인증된 UUID·이메일·학급 조건의 재조회 결과만 사용한다. 조회 후 갱신하는 방식이 아니므로 조회/삽입 사이 경쟁에서도 기존 행을 병합하지 않는다. 연결 불가 시 409와 “기존 자료의 소유자 확인이 필요합니다. 관리자에게 문의해 주세요.”를 반환하며 학급 기억·쿠키 설정으로 진행하지 않는다.

학급 POST와 최초 학급 준비는 동일한 createOwnedClassroom 경로를 사용한다. 기존 학급 읽기는 계속 owner_id 조건을 사용하며 추가 쓰기를 하지 않는다. 정상 소유자가 같은 학급을 다시 생성 요청하면 기존 행을 그대로 재사용한다. 학교명 수정은 생성 재요청으로 처리하지 않는다.

[PostgREST 공식 문서](https://docs.postgrest.org/en/stable/references/api/tables_views.html)의 충돌 무시 옵션을 사용했다. 스키마·기존 행의 소유권·운영 자료는 변경하지 않았다.

## 명시적 인계 원칙

일반 가입·로그인·학급 추가는 인계 동작이 아니다. NULL/다른 UUID 충돌은 자동 연결하지 않는다. 인계가 필요하면 본인·자료 소유 확인, 대상 행과 기존 지문 확인, 중복 학급·자식 영향 검토, 승인된 조건부 변경 및 감사·롤백 절차를 적용한다. 세부 방안은 [조사 문서](UNLINKED_AUTH_AUDIT_2026-11-03.md)를 따른다. 이번 수정에 셀프서비스 인계 API나 관리자 인계 UI를 추가하지 않았다.

- 타입 검사·변경 파일 린트, 전체 빌드 및 기존 테스트 217개(75+142) 통과.
- 기존 소스 문자열 검사는 학급 POST의 변수명 변경으로 PUT 이전 위치를 잘못 찾았으므로 학급 선택 검사를 PUT 구간에 한정함.
- 개발 시점에는 실제 DB/PostgREST 통합 및 운영 검증을 실행하지 않았다. 이후 기존 운영 계정 로그인·학급 조회는 아래 배포 후 기록에서 확인했다. 소유권 충돌의 운영 재현은 하지 않았으며 모의 동시성 검사가 실제 DB 부하 검증을 뜻하지 않는다.
- 교사 준비와 학급 생성은 별도 요청이다. 새 교사 삽입 후 학급 충돌이 발견되면 새 교사 행이 남을 수 있으나 기존 행을 덮어쓰지는 않는다. 다른 유니크 제약 충돌·DB 오류는 안전하게 실패할 수 있으며 임의 소유권 연결로 우회하지 않는다.
